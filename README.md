# Ubilling User Bot

Telegram-бот личного кабинета абонента для биллинговой системы [Ubilling](https://ubilling.net.ua/).

## Возможности

- Авторизация через логин/пароль или deep link
- Просмотр баланса и истории платежей
- Оплата онлайн и активация карт оплаты
- Просмотр и смена тарифов
- Тикеты техподдержки
- Живой чат с поддержкой через Telegram-группу (реакции-статусы, авто-закрытие)
- Заморозка/разморозка аккаунта
- Кредит
- Информация об аккаунте и провайдере
- Мультиязычный интерфейс (uk/ru/en)

## Запуск

### Docker (production)

```bash
git clone https://github.com/Fenicu/ubilling_user_bot.git
cd ubilling_user_bot

cp .env.example .env
# Отредактируйте .env — укажите BOT_TOKEN и UBILLING_URL

docker compose up -d
```

Бот, PostgreSQL и Redis поднимутся автоматически. Миграции БД применяются при старте контейнера.

Логи:

```bash
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

### Локально (для разработки)

Требуется Python 3.13+, [uv](https://docs.astral.sh/uv/), запущенные PostgreSQL и Redis.

```bash
# Установка зависимостей
uv sync

# Конфигурация
cp .env.example .env
# Отредактируйте .env — укажите BOT_TOKEN, UBILLING_URL
# и поменяйте хосты на localhost:
#   DATABASE_URL=postgresql+asyncpg://bot:bot@localhost:5432/bot
#   REDIS_URL=redis://localhost:6379/0

# Применение миграций
uv run alembic upgrade head

# Запуск бота
uv run python -m bot
```

## Конфигурация

Все параметры задаются через переменные окружения (файл `.env`):

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен Telegram-бота | — |
| `DATABASE_URL` | Строка подключения к PostgreSQL | `postgresql+asyncpg://bot:bot@postgres:5432/bot` |
| `REDIS_URL` | Строка подключения к Redis | `redis://redis:6379/0` |
| `UBILLING_URL` | URL Ubilling XMLAgent (userstats) | — |
| `UBILLING_UBER_KEY` | MD5 серийного номера (extended auth) | — |
| `SESSION_TTL_HOURS` | Время жизни сессии (-1 = бессрочно) | `-1` |
| `DEFAULT_LOCALE` | Локаль по умолчанию | `uk` |
| `LOG_LEVEL` | Уровень логирования | `DEBUG` |
| `SUPPORT_CHAT_ID` | id группы поддержки (пусто = чат поддержки выключен) | — |
| `SUPPORT_TOPIC_ID` | id топика в группе (пусто = общий поток группы) | — |
| `SUPPORT_REACTION_UNANSWERED` | реакция на сообщение без ответа | `👀` |
| `SUPPORT_REACTION_ANSWERED` | реакция на отвеченное сообщение | `👌` |
| `SUPPORT_REACTION_UNDELIVERED` | реакция на недоставленное сообщение | `💔` |
| `SUPPORT_AUTOCLOSE_HOURS` | авто-закрытие диалога после N часов неактивности (`0`/`-1` = выключено) | `48` |

## Deep link авторизация

Бот поддерживает авторизацию через deep link:

```
https://t.me/<bot_username>?start=<login>-<password_md5>
```

где `<password_md5>` — MD5-хеш пароля пользователя.

## Чат поддержки

Живой чат «абонент ↔ оператор» поверх Telegram: сообщения абонента дублируются в
отдельную группу (опционально — в конкретный топик), ответ оператора — reply на
сообщение в группе, абоненту он приходит анонимно от имени бота. Статусы сообщений
показываются реакциями бота. Фича выключена, пока не задан `SUPPORT_CHAT_ID`.

### Настройка группы

1. Создать супергруппу (обычную или форумную — форум даёт темы, тогда поддержку
   удобно вынести в отдельный топик).
2. Добавить бота в группу. **Админ-права боту не нужны** — ни для простановки
   реакций (`setMessageReaction` работает и без них), ни для reply-роутинга ответов.
3. В настройках группы → «Реакции» — включить реакции и разрешить нужные эмодзи.
   Это общегрупповая настройка: без неё Telegram отклонит любую реакцию бота, даже
   стандартную. Право участников `can_react_to_messages` тут ни при чём — бот ставит
   реакции вызовом Bot API, а не как обычный участник.
4. Если завели топик — получить его id (см. ниже) и указать в `SUPPORT_TOPIC_ID`.

### Как узнать SUPPORT_CHAT_ID и SUPPORT_TOPIC_ID

Два равноценных способа.

**Способ 1 — @getidsbot.** Перешлите любое сообщение из группы (если группа с
темами — прямо из нужного топика) боту [@getidsbot](https://t.me/getidsbot): в
ответ придут `chat_id` и `thread_id` (это и есть `topic_id`).

**Способ 2 — «Копировать ссылку».** Долгий тап (или правый клик) по любому
сообщению в группе → «Копировать ссылку». Получится ссылка вида:

```
https://t.me/c/2233445566/7/12
```

- `chat_id` = `-100` + первое число → `-1002233445566`
- `topic_id` = второе число → `7`
- третье число — id самого сообщения, не нужен

Если группа без тем, ссылка короче (`https://t.me/c/2233445566/12`) — тогда
`SUPPORT_TOPIC_ID` оставьте пустым, сообщения пойдут в общий поток группы.

### Кастомные реакции — пошагово

По умолчанию бот ставит стандартные эмодзи 👀 (не отвечено) / 👌 (отвечено) /
💔 (не доставлено). Чтобы использовать кастомные эмодзи (из собственного набора):

1. Выбрать или создать набор кастомных эмодзи в Telegram.
2. В настройках группы → «Реакции» — явно разрешить нужные кастомные эмодзи
   (по умолчанию группа разрешает только стандартные, кастомные — по одному).
3. Отправить в группу (в нужный топик) сообщение с этим эмодзи — текстом или в
   подписи к медиа — и реплаем на него выполнить `/emoji_id`. Бот ответит списком
   пар «эмодзи → custom_emoji_id»:

   ```
   ❓ → 5368324170671202286
   ```

4. Скопировать id и прописать в `.env`, например:

   ```
   SUPPORT_REACTION_UNANSWERED=5368324170671202286
   ```

5. Перезапустить бота (`docker compose restart bot` или аналог) — значения
   читаются один раз при старте.

Важно:

- У бота **одна реакция на сообщение** — статус заменяется, а не накапливается
  (было 👀 → стало 👌, а не 👀+👌 одновременно).
- Платные реакции (со звёздами) ботам недоступны.
- **Premium-подписка владельца бота не нужна.** Кастомные эмодзи здесь используются
  только в реакциях (`setMessageReaction`) — фича не вставляет кастом-эмодзи в текст
  сообщений (это отдельная Premium-возможность Bot API, её бот не использует).

### Если реакция не ставится (fallback)

Если настроенный кастом-эмодзи не разрешён в группе или в id опечатка, Telegram
отклоняет вызов, и бот:

- пишет в лог предупреждение вида
  `support.reaction fallback: настроенная реакция роли 'unanswered' отклонена, переключаюсь на дефолт`;
- откатывается на дефолтную реакцию роли (👀/👌/💔) для всех последующих сообщений —
  до перезапуска процесса (сбойная роль запоминается только в памяти, чтобы не
  долбить API заведомо битой реакцией);
- на доставку сообщений это не влияет — реакция ставится best-effort.

Как починить:

1. Найти `support.reaction fallback` в логах: `docker compose logs bot | grep "support.reaction"`.
2. Проверить, что нужный эмодзи явно разрешён в «Реакции» настроек группы.
3. Проверить `custom_emoji_id` заново через `/emoji_id` — возможно, опечатка.
4. Исправить `.env` и перезапустить бота.

### Работа в группе/топике

- **Ответ оператора** — reply на сообщение абонента (или на карточку/шапку медиа) →
  доставляется абоненту анонимно (копией, не форвардом); реакция «отвечено»
  ставится на реплайнутое сообщение и на все более ранние неотвеченные сообщения
  диалога.
- **`/close`** реплаем на любое сообщение диалога — закрывает диалог, абоненту
  приходит уведомление о закрытии.
- **Кнопка «🔒 Закрыть диалог»** на карточке абонента — тот же эффект в один клик;
  доступна любому участнику группы (сама группа и есть контроль доступа).
- **Авто-закрытие** — фоновая задача раз в час закрывает диалоги, неактивные дольше
  `SUPPORT_AUTOCLOSE_HOURS` часов; `0` или `-1` выключает авто-закрытие.
- **Whitelist типов сообщений** (в обе стороны): текст, фото, видео, документ,
  голосовое, видеосообщение, аудио, стикер. Остальное (опросы, локации, контакты и
  т.п.) отклоняется вежливым сообщением и не пересылается на другую сторону.
- **`/emoji_id`** реплаем на сообщение с кастом-эмодзи — показывает пары
  «эмодзи → custom_emoji_id» (из текста и подписи; по стикерам не работает).

### Ограничения

- Premium у владельца бота не нужен — фича использует только реакции сообщений, не
  кастом-эмодзи в тексте.
- У бота максимум одна реакция на сообщение.
- На абонента — не более одного открытого диалога одновременно (история хранится
  вся, лимита тем/диалогов нет: всё обращение идёт в один топик).
- Альбомы (несколько фото/видео одной media group) доставляются как отдельные
  сообщения, без специальной склейки.
- Ответ оператора всегда анонимный — подписи оператора нет.
